# ksw2
记录了对双序列比对的学习，主要是参照原作者的代码风格，实现对从 NW 到 SW 的改写。 
学习对象：https://github.com/lh3/ksw2 

## 引用文件介绍

* `ksw2.h`：头文件，包含主要数据结构与接口声明。
* `ksw2_gg.c`：全局比对；Green 的标准 DP 形式。
* `ksw2_gg2.c`：全局比对；Suzuki 的对角线形式。
* `ksw2_gg2_sse.c`：全局比对；基于 SSE intrinsics 的 Suzuki 对角线向量化实现。

## 改写文件介绍

* `ksw2_sw.c`：基于 `ksw2_gg.c` 改写得到的标准 DP 版 SW
* `ksw2_sw2.c`：基于 `ksw2_gg2.c` 改写得到的对角线版 SW（尚未完成）
* `ksw2_sw2_sse.c`：基于 `ksw2_gg2_sse.c` 改写得到的 SSE 向量化 SW（尚未完成）
* `ksw_sw_traceback.h`：基于 `ksw2.h` 中 **ksw_backtrack** 函数，重写了属于 SW 的回溯函数

## 名词解释

* **匹配（match）**：两条序列在某一位匹配成功（字符相同），会得到加分奖励
* **错配（mismatch）**：两条序列在某一位匹配失败（字符不同），会得到扣分惩罚
* **gap open**：新添加一个空位的惩罚 q（类似起步价，一般比较大）
* **gap extension**：每再添加一个空位的惩罚 r（一般比较小）
* **全局比对（global alignment）**：比较两条完整的序列
* **局部比对（local alignment）**：比较两条序列的某一片段
* **traceback**：回溯，在完成 DP 后，通过终点进行回溯到原点，可以得到一个最优添加空位的序列方案
* **CIGAR**：通过字符串记录回溯得到的序列（如 6M2I2M），M（match/mismatch）比对的字符、I（insertion）target 插入的空格、D（deletion）query 插入的空格，矩阵或回溯描述等信息可以由该字符串表示。

## 在 `ksw2_gg.c` 中

### 主要的函数：

```c
int ksw_gg(void *km, int qlen, const uint8_t *query, int tlen, const uint8_t *target, int8_t m, const int8_t *mat, int8_t gapo, int8_t gape, int w, int *m_cigar_, int *n_cigar_, uint32_t **cigar_)
```

#### 函数中传入的参数

| 参数名                           | 角色                                              | 作用                                       |
| -------------------------------- | ------------------------------------------------- | :----------------------------------------- |
| `km`                             | 内存池地址                                        | 负责算法内部的高速内存分配                 |
| `qlen`, `query`                  | `Query` 串的长度及其本身地址                      | 纵轴 $i$，待检测的高通量 `Reads`           |
| `tlen`, `target`                 | `Target` 串的长度及其本身地址                     | 横轴 $j$，权威的基因组参考标准             |
| `m`, `mat`                       | 打分矩阵（维度与指针）                            | 规定 $5 \times 5$ 的 `Match/Mismatch` 规则 |
| `gapo`, `gape`                   | 空位罚分（开启惩罚和延伸惩罚）                    | 开启和延续 `Gap` 的扣分底牌                |
| `w`                              | 带宽                                              | 框定 DP 的带状剪枝边界 `[beg, end)`        |
| `m_cigar_`, `n_cigar_`, `cigar_` | 输出的结果`CIGAR`字符串（大小、片段数、二维指针） | 回溯路径（M/I/D）的信息                    |

### 状态定义

| 状态      | 物理意义                                                     | 视觉表现            | 状态转移（外层 $i$ 代表 Target 字符，内层 $j$ 代表 Query 字符） |
| --------- | ------------------------------------------------------------ | ------------------- | ------------------------------------------------------------ |
| $H(i, j)$ | **主状态 (Match / Mismatch)** ；当前 Target 字符与 Query 字符强行对齐的最优评分。 | Target: A Query: A  | 必须从**左上角对角线** $(i-1, j-1)$ 转移过来                         |
| $E(i, j)$ | **水平空位状态 (Insertion)**；相对于 Target 来说，Query 插入了字符，Target 插入空位。 | Target: - Query: A  | 必须从**左边格子** $(i, j-1)$ 转移过来                                     |
| $F(i, j)$ | **垂直空位状态 (Deletion)**；相对于 Target 来说，Query 缺失了字符，Query 插入空位。 | Target: A Query:  - | 必须从**上边格子** $(i-1, j)$ 转移过来                                     |

### 结构体定义：

```c
typedef struct { int32_t h, e; } eh_t; 
```

* 用 eh_t.h 存储 $H(i)(j-1)$, eh_t.e 存储 $E(i+1)(j)$
  由于为了节省空间，用了滚动优化，所以当遍历到下一层i时，可以从 $eh$ 中直接读取到 $H(i-1)(j-1)$ 和 $E(i)(j)$ 以便后续状态转移

### 状态转移方程（NW）

$$
\begin{aligned}
H(i,j) &= \max\{(H(i-1,j-1)+S(i,j), E(i,j), F(i,j))\} \\
E(i+1,j) &= \max\{(H(i,j)-\mathrm{gapo}, E(i,j))\} - \mathrm{gape} \\
         &= \max\{(H(i,j)-\mathrm{gapoe}, E(i,j)-\mathrm{gape}\)} \\
F(i,j+1) &= \max\{(H(i,j)-\mathrm{gapo}, F(i,j))\} - \mathrm{gape} \\
         &= \max\{(H(i,j)-\mathrm{gapoe}, F(i,j)-\mathrm{gape})\}
\end{aligned}
$$

## 在 `ksw2_sw.c` 中

### 状态转移方程（SW）

$$
\begin{aligned}
H(i,j) &= \max\{(0, H(i-1,j-1)+S(i,j), E(i,j), F(i,j))\} \\
E(i+1,j) &= \max\{(0, H(i,j)-\mathrm{gapoe}, E(i,j)-\mathrm{gape})\} \\
F(i,j+1) &= \max\{(0, H(i,j)-\mathrm{gapoe}, F(i,j)-\mathrm{gape})\}
\end{aligned}
$$
## 在 `ksw2_gg2.c` 中

#### 变量代换

* 令 $u_{i,j} = H_{i,j} - H_{i-1,j} + qe$  （竖直方向 $H$ 的差分+非负偏移量）
* 令 $v_{i,j} = H_{i,j} - H_{i,j-1} + qe$  （水平方向 $H$ 的差分+非负偏移量）
* 令 $x_{i,j} = E_{i+1,j} - H_{i,j} + qe$  （$E$ 状态与 $H$ 的差分+非负偏移量）
* 令 $y_{i,j} = F_{i,j+1} - H_{i,j} + qe$  （$F$ 状态与 $H$ 的差分+非负偏移量）
* 得 $z_{i,j} = H_{i,j} - H_{i-1,j-1} + 2qe = \max\{(S_{i,j}+2qe,  x_{i-1,j}+v_{i-1,j},  y_{i,j-1}+u_{i,j-1}) \}$ （对角线方向 $H$ 的差分+非负偏移量）
* 得 $u_{i,j} = z_{i,j} - v_{i-1,j}$ 
* 得 $v_{i,j} = z_{i,j} - u_{i,j-1}$ 
* 得 $x_{i,j} = \max\{(0, x_{i-1,j} - u_{i,j} + q)\} = \max\{(0, x_{i-1,j} + v_{i-1,j} - z_{i,j} + q)\}$ 
* 得 $y_{i,j} = \max\{(0, y_{i,j-1} - v_{i,j} + q)\} = \max\{(0, y_{i,j-1} + u_{i,j-1} - z_{i,j} + q)\}$ 
* 通过偏移量，保证了每个变量的非负性 

#### 仿射变换

* 令 $r = i + j$ ,  $t = i$ 
* 得 $z_{r,t}=\max\{(S(t,r-t)+2qe,x_{r-1,t-1}+v_{r-1,t-1},y_{r-1,t}+u_{r-1,t})\}$ 
* 得 $u_{r,t}=z_{r,t}-v_{r-1,t-1}$ 
* 得 $v_{r,t}=z_{r,t}-u_{r-1,t}$ 
* 得 $x_{r,t}=\max\{(0,x_{r-1,t-1}+v_{r-1,t-1}-z_{r,t}+q)\}$ 
* 得 $y_{r.t}=\max\{(0,y_{r-1,t}+u_{r-1,t}-z_{r,t}+q)\}$ 
* 可知 $0\le r\le qlen + tlen-2$  与 $\max \{(0,r-qlen+1,\frac{r-w}{2})\}\le t\le\min\{(tlen-1,r,\frac{r+w}{2})\}$

## 在 `ksw2_sw2.c` 中

在 `ksw2_gg2.c` 的基础上，SW 局部比对的实现面临一个关键挑战：**最优比对终点不固定**，无法像 NW 全局比对那样直接确定回溯起点。为此，代码引入了 `H0`、`H1`、`H2` 三个数组，分别维护当前层（`r`）、上一层（`r-1`）和上两层（`r-2`）的 H 值，在递推过程中精确追踪每一个格子的真实 H 值，从而实时记录全局最高分及其位置。

### **为什么需要三个数组？**

旋转坐标下，`r = i + j`，一次（对角线移动的）匹配使 `r` 增加 2。因此，计算当前格 `H(r, t)` 的匹配候选值时，需要依赖 `H(r-2, t-1)`——即上两轮的数据。三个数组正好满足了这一依赖：

- `H2[t-1]`：提供 `r-2` 轮的 H 值，用于计算匹配候选
- `H1[t]`：提供 `r-1` 轮的 H 值，用于计算删除候选
- `H0[t-1]`：提供当前轮左侧的 H 值，用于计算插入候选

每轮计算完成后，通过指针轮换实现“滚动”效果——`H2 ← H1 ← H0`，无需复制数组，高效且清晰。

### **解决了什么问题？**

在纯差分变量（`u/v/x/y`）的框架下，H 值被压缩为相对量，无法直接获得绝对分数，也就无法定位最优回溯起点。引入 `H0/H1/H2` 后，每一格的精确 H 值都被追踪，`max_score` 和对应的 `(end_r, end_t)` 得以在递推过程中实时更新。最终，回溯函数从该最高分位置出发，沿 `p` 矩阵中存储的方向信息反向行走，遇到 `0xff` 标记（SW 的“重新开始”位置）时停止，从而生成正确的局部比对 CIGAR。

### H的状态转移方程（SW2）

匹配：$H(r,t) = H(r-2, t-1) + S(i,j)$

删除：$H(r,t) = H(r-1, t) - q - e$

插入：$H(r,t) = H(r, t-1) - q - e$

最终在三种情况里取最优 H
## 在 `ksw2_gg2_sse.c` 中

* **SIMD（Single Instruction, Multiple Data）**：用一条指令，同时对多组数据执行相同的操作

* **SSE（Streaming SIMD Extensions）**：是一种 SIMD 指令集，它引入了一种特殊的**向量寄存器**，宽度为 **128 位**（16 字节），这意味着，一个 SSE 寄存器可以一次性容纳 16 个 `int8_t` 类型的整数。因此，理想情况下，SSE 版本的一个 `_mm_add_epi8` 指令，其计算吞吐量是标量 `a + b` 的 **16 倍**。这就是向量化能带来巨大性能提升的根本原因。

  | 操作   | 标量版本 (`ksw2_gg2.c`)       | SSE 版本 (`ksw2_gg2_sse.c`)            |
  | ------ | ----------------------------- | -------------------------------------- |
  | 加法   | `a + b`（一次加一对）         | `_mm_add_epi8(a, b)`（一次加 16 对）   |
  | 比较   | `a > z`（一次比一对）         | `_mm_cmpgt_epi8(a, z)`（一次比 16 对） |
  | 最大值 | `a > z ? a : z`（一次取一对） | `_mm_max_epu8(z, a)`（一次取 16 对）   |

  **性能提升**：理想情况下，内层循环的吞吐量提升约 10-16 倍。

* 数据打包进向量寄存器的方法：在 `ksw2` 的 SSE 实现中，所有核心状态（`u`, `v`, `x`, `y` 等）都存储为 `int8_t` 数组，并且是**连续且按16字节对齐**的。这使得我们可以使用 SSE 的**加载（Load）**和**存储（Store）**指令，一次搬移 16 个数据。

  ```c
  // SSE：
  // 一次性从内存地址开始，加载 16 个连续的 int8_t 数据
  // 这些数据被装入一个 128 位的向量寄存器中
  __m128i xt1 = _mm_load_si128(&x[t]);   // 加载 x[t..t+15]
  __m128i vt1 = _mm_load_si128(&v[t]);   // 加载 v[t..t+15]
  __m128i ut  = _mm_load_si128(&u[t]);   // 加载 u[t..t+15]
  __m128i yt  = _mm_load_si128(&y[t]);   // 加载 y[t..t+15]
  
  _mm_store_si128(&u[t], u_new);   // 将 16 个值写回 u[t..t+15]
  _mm_store_si128(&v[t], v_new);   // 将 16 个值写回 v[t..t+15]
  ```

* 向量化后如何保持与标量版本等价：

（1）向量移位：

```c
xt1 = _mm_load_si128(&x[t]);          // xt1 = [x_t, x_{t+1}, ..., x_{t+15}]
tmp = _mm_srli_si128(xt1, 15);         // tmp = [x_{t+15}, 0, ..., 0]
xt1 = _mm_or_si128(_mm_slli_si128(xt1, 1), x1_); // xt1 = [x_{t-1}, x_t, x_{t+1}, ..., x_{t+14}]
x1_ = tmp;                             // 保存 x_{t+15} 供下一组使用
```

这样，向量中的第 `i` 个元素正好是第 `i-1` 个元素的值，完美模拟了标量循环中 `x1 = x[t-1]` 的依赖关系。

（2）边界条件处理：

```c
st = st / 16 * 16;               // 向下对齐到 16 的倍数
en = (en + 16) / 16 * 16 - 1;   // 向上对齐到 16 的倍数 - 1
```

向量化循环会多处理一些边界外的格子，但它们的值会被边界条件置为 0（差分偏移后的 `-∞`），因此不影响结果。

（3）H0 追踪使用原始边界：

```c
if (last_H0_t >= st0 && last_H0_t <= en0)  // 使用 st0/en0，而不是 st/en
    H0 += ((uint8_t*)v)[last_H0_t] - (q + e);
```

H0 追踪使用原始的 `st0/en0` 边界，避开向量化填充的无效数据，保证分数计算正确。

* 为什么 Suzuki 形式更适合做宽向量并行：

（1）依赖方向：一维 vs 二维

| 公式                | 依赖方向                                  | 向量化难度                                        |
| ------------------- | ----------------------------------------- | ------------------------------------------------- |
| **Green 公式**      | `H(i,j)` 依赖左、上、左上                 | **困难**：数据在二维平面发散，无法用一维向量表达  |
| **Suzuki 旋转坐标** | `(r,t)` 只依赖 `(r-1, t-1)` 和 `(r-1, t)` | **容易**：所有依赖都在上一轮 `(r-1)` 的一维数组中 |

（2）数据访问模式：在 `ksw2_gg2_sse.c` 中，所有向量都是连续存储的，且访问是顺序的，完美契合 SIMD 的“连续加载 + 批量处理”模式，而 Green 公式中，`H(i,j)` 需要同时访问 `(i-1,j)`、`(i,j-1)` 和 `(i-1,j-1)`。这三个位置在内存中不是连续的，无法用一条 SSE 加载指令一次性获取。

（3）差分值的数值范围：经过非负偏移后，Suzuki 公式的差分值 `u, v, x, y` 都在 `[0, 127]` 范围内可以安全地使用 `uint8_t` 存储和 `_mm_max_epu8`（无符号最大值）等高效指令。如果是 Green 公式的原始 H 值，范围可能超出 `int8_t` 的限制。
